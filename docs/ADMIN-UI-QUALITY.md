# MCP Gateway Admin UI Quality Standard

**Scope:** Every current and future Gateway Administration page (Targets, Users, Target Groups, AI clients, Operations, Activity, Connection and authentication). This is the durable review checklist for new UI, modifications and regression fixes; it does not authorize production deployment. The source of implementation truth is [admin.css](../public/css/admin.css) and existing [Blade views](../resources/views/admin). Keep changes consistent with [Development](DEVELOPMENT.md#admin-ui-foundation).

## Shared visual and spacing rules

- Use the shared `--ui-*` tokens for color, text, surfaces, borders, radii, controls and focus. Add a new token only for a genuinely reused rule; no duplicate page-specific palettes or local components that conflict with shared CSS.
- **No touching independent surfaces:** adjacent top-level panels and content grids/stacks inside `.main-content` must have at least `--ui-panel-stack-gap` (currently **1.25rem**) of block-axis breathing room. This includes Edit Target panels, AI-client panels, and Dashboard Needs review followed by its content grid. One shared selector, `.main-content > :is(.panel, .content-grid, .content-stack) + :is(.panel, .content-grid, .content-stack)`, owns this rhythm. Use `.content-stack` for a deliberately stacked group of panels; do not add view-specific margins.
- Section headings leave `--ui-panel-stack-gap` before a following native form or feedback alert. The shared adjacency rule also covers one feedback alert between heading and form; it sets the same block-start margin as existing `.form-stack`, without additive page padding or doubled gaps. Heading-to-table rhythm remains independent.
- **One inherited outer canvas:** every authenticated Admin page uses the same `--ui-workspace-max` (106rem) and responsive `.shell` gutters for header breadcrumbs, heading/actions and main content. Forms and inventories do not select different outer widths. Authenticated panels fill their parent: standalone panels align to the canvas, while intentional Dashboard/content-grid panels fill their grid cell. Do not add per-page panel maxima, sidebar offsets or nested workspace wrappers. `@section('form-page', '1')` only marks readable internal field composition; it must never narrow the outer frame. Guest authentication cards retain their separate sizing.
- Within a permission fieldset, adjacent `.permission-category` groups use shared `--ui-panel-stack-gap` block-start separation **before** their divider; the divider then has its normal internal padding before heading/help/cards. A trailing `Already unavailable in this Role` disclosure also leaves that shared gap after the last section, even when its Owner note sibling is hidden. This is a shared User/Target Group/Target rule, not a User-page margin override; keep it stable in RTL, narrow widths and both themes.
- Permission-option copy must grow to fill the space after the checkbox. Scope badges align to the logical trailing edge independently of title/help length; long labels and badges may wrap without escaping the card, including RTL/localized content.
- Explanatory prose stays in semantic source order, never CSS newspaper columns. The AI clients page uses a labelled `.panel-note` with a brief section explanation and three semantic `.lifecycle-card` articles (icon, heading and complete explanatory paragraph) in the responsive `.lifecycle-cards` grid. It belongs to the client profiles above, not the independent authorization table below. Reuse existing tokens, preserve all lifecycle text, and let cards automatically stack as available space or text size shrinks; no extra elevated wrapper or orphaned note. Short heading/field help may retain an internal `.reading-width`; it is not an outer panel width.
- Add and Edit Target share the existing `.target-field-grid` for identity fields, with long guidance spanning both columns; do not place a narrow standalone form field on one side of an otherwise empty full-width panel.
- Distinguish major sections (separate panels), subordinate groups (e.g. `.target-subsection` within a panel) and fields (`.field`). A border between internal fields is not a substitute for spacing between cards. Use shared `.form-stack` or `.form-grid`, not manual `<br>` gaps or arbitrary inline styles.
- A page title and its action/navigation row must remain separate from cards. Respect established page-heading, table, alert and pagination spacing without doubling their margins. Use logical properties such as `margin-block-start` and `padding-inline` so direction changes do not break the layout.
- Buttons are visually and functionally grouped near their action; primary actions are distinguishable, secondary navigation is consistent, destructive actions have deliberate confirmation. Do not stack an unbroken wide control set across narrow screens.

## Responsive, legible and accessible states

- Inspect at a narrow phone width (360–390px), tablet (768px), and wide desktop (at least 1280px) when rendering is available. Two-column fields become a single column before labels/inputs collide. Inputs, long URLs, host keys and identifiers must not overflow or create horizontal scrolling outside explicitly scrollable tables/navigation.
- Use semantic heading order, visible labels, clear field help, effective error messages and keyboard-operable form controls. Keep visible `:focus-visible`, full-label checkbox targets and sufficient text/background contrast. Never rely only on color to convey connected/error/danger/disabled states.
- Show actionable failures, status and recovery guidance with safe correlation IDs. No raw secrets, access tokens, passwords, private keys or remote HTTP bodies in UI/log diagnostics. Error, pending, empty, loading and saved states should not shift controls into unreadable or overlapping positions.
- Keep the optional Add Target endpoint preflight control and status in the shared enrollment action area, available for each explicitly supported connector; it must not be hidden inside one connector panel or imply a successful network preflight verifies authentication or the remote system identity. A successful check must identify its exact checked subject, and changing the selected connector or any checked endpoint field must invalidate that result with an accessible status announcement.
- Verify both light and dark media preference, reduced-motion setting, longest realistic localized text, and RTL-compatible layout when relevant. Keep text wrapping, sufficient touch targets and readable monospace/code snippets.
- Preserve server-rendered Blade, escaped output, CSRF, per-user/Target permissions, redaction, Owner password reauthentication and the current security/transport boundaries. UI polish must not silently relax behavior.

## Connector and navigation consistency

- Shared shell, field/table, feedback and evidence patterns are connector-neutral. Connector companions supply only reviewed local content/partial references; preserve their distinct authentication/recovery meaning and existing server authority. Unknown types must not inherit SSH or WordPress claims.
- Dashboard counts, review list and review-filtered inventory share the same scoped predicate. Show all lifecycle states, and explain that Pause and review indicators overlap lifecycle totals. Recorded connected is never a live health verdict.
- Put Connection/recovery before general operations on Target details. Keep uncertainty visible and retain useful authorized diagnostic codes, messages, paths/context and correlation; redact actual secrets precisely.
- Preserve native forms and one-use/file/auth routes during enhanced GET navigation. Explicitly disable application snapshot caches/prefetch, refresh server-authorized navigation, and check direct URLs, Back/Forward, unsaved forms, session/permission changes, focus/title, repeated widget initialization and coherent asset updates. Native/no-JS navigation remains usable.

## Access collection consistency

- Group pages open on current members, with available-member pickers and persistent Group/User context. Use one native explicit-selection pattern across group Targets, group Users, user Groups and direct user Targets; keep search, 50-row pages and bounded 100-item review usable without JavaScript.
- A visible permission restriction must say **Deny** and explain that checked means blocked. Edit User presents its current global Deny choices expanded by default, with saved/unsaved counts and explicit distinction from effective role/Group/Target permissions. Create User can keep advanced restrictions collapsed. Keep name/role/scope controls primary and advanced restriction matrices separate; never invert the existing denied-permission request contract or clear default SSH blocks for presentation.
- For User create/edit, a Role change must immediately distinguish editable Deny restrictions from capabilities already excluded by that Role; no out-of-role checkbox may remain keyboard-focusable or submit from the normal enhanced form. **Operator and Administrator SSH command/SFTP capabilities belong to the Role, but all three start as checked global Denies on fresh new users**: editable does not mean granted. An existing SSH-capable user's saved choices must not be overwritten, and first unsaved promotion from Viewer/Owner must present fail-closed SSH Denies in both JS and native GET preview. Draft choices remain intact on subsequent Role switching. Owner displays unrestricted recovery meaning rather than an invented list of unavailable capabilities. Preserve a no-JS Role-preview GET followed by normal save, with server-side Owner confirmation, Selected Target scope, and SSH safeguards remaining authoritative. Sibling Target Group and Target editors must not inherit User Role filtering.
- Selection and review tables share a readable identity-cell minimum width. Keep any extra width inside the labelled, keyboard-focusable `.table-wrap`, with a visible horizontal-scroll hint and shared focus styling. In ordinary block flow, leave shared breathing room between the hint and the table focus ring; preserve native table semantics and do not widen the document.
- Keep exact selected identities across search and paging. The progressive count includes current-page checks and saved off-page choices; native fallback identifies the server-saved count. A different operation/intent cannot silently inherit hidden selections.
- The review must show concrete current/requested states, changed/unchanged counts and applicable consequences. Preserve the reviewed snapshot after password errors, require a new review after stale state, and never treat an old tab as approval of a newer selection. Follow [the access workflow contract](ADMIN-ACCESS-WORKFLOWS.md).

## Acceptance and durable regression discipline

1. Identify which shared layout class/token owns a visible problem. **Fix that one shared rule**; review every view using it for side effects. Do not bury a repeated issue with a special class on the latest page.
2. Include the specific reproduced state (e.g. two adjacent top-level panels, long SSH host, inline error, restricted Owner permissions) in the smallest applicable PHPUnit/feature regression. `tests/Feature/Admin/AdminUiPresentationTest.php` protects shared stylesheet and markup contracts.
3. Validate CSS syntax/changed-source assertions and relevant Admin feature tests. For visual changes, inspect actual browser geometry at desktop and mobile when a safe test session is available; check independent card gaps, focus, overflow, contrast and both theme variants. Mark visual browser testing **NOT TESTED** if it cannot be run; CSS grep is not a screenshot test.
4. In review, explicitly compare the touched screen **and at least one sibling surface** reusing the same component. Record deviations that are required vs future polish; do not create a heavy CI/browser requirement solely for cosmetic changes, but never label untested visuals as verified.
5. Do not change public release tags or deployed operator installations as part of a stylesheet/documentation fix. Follow the repository's exact-source validation, review, integration and release approval gates.
